Build a workspace called "Client Onboarding" for RevGravy, a HubSpot consultancy, to run Marketing, Sales and Service Hub onboardings. Build only the projects, tables, columns, views, sections, tasks and subtasks below. Don't create agents (I'll create them in the agent builder), documents or forms.

HOW WE'LL USE IT
- Day 0 is the day the customer's deal reaches "Start Payment Received" in our Sales Pipeline. Programs last 60 to 90 days; the task days below are for a 90-day program.
- Every customer gets the Core tasks once, plus one module per hub they bought (Marketing Hub, Sales Hub, Service Hub).
- All customers share the same tables, and each row links to its Customers row, so agents work across all customers.
1. Add a row to Customers: Customer, Company, Deal, Architect, Program length, Start date (the payment date), Products purchased, hub tiers, From→To goal, FigJam and Supered links.
2. Tick Create tasks. The Task Generator copies the Core tasks once, plus one module for each product purchased, into Customer Task. It fills the dates, assigns the Architect, sets Tasks created for, and unticks Create tasks.
3. If the customer buys another hub later, add it to Products purchased and tick Create tasks again. Only the new hub's tasks are added.
4. To work on one customer, filter any view by Customer. 'My tasks' shows an Architect's work across all their customers.
5. Share the workspace with Phil and the Architects (it's private by default).

PROJECT 1: "Onboarding Task Library"
The master task list. Nobody works in it; customers' tasks are copied from it.

Table "Task Library" with these columns, in this order:
- Task ID (Text): e.g. 4.07 (Core) or MH-4.03 (Marketing Hub). First column, so 'Depends on' can be read
- Task (Text): Task name
- Module (Dropdown): Core, Marketing Hub, Sales Hub, Service Hub
- Status (Dropdown): Not started, In progress, Waiting on client, In review, Done, Won't do
- Owner role (Dropdown): Phil, Architect, Ops, Client POC
- Assignee (HubSpot user): Person doing it
- Due date (Formula): Project Day 0 + Due day, compressed by Program length (see rule)
- Client-facing (Yes/No): Does the customer see or do this?
- Repeats (Text): Weekly, Monthly, etc.
- Depends on (Text): Task IDs
- Definition of done (Long text): What 'done' means
- Notes (Long text): Anything else
- Section (Dropdown): Phase: P0 to P9 (hidden in Main table)
- Start day (Number): Days after Day 0, 90-day plan (hidden)
- Due day (Number): Days after Day 0, 90-day plan (hidden)
- Start date (Date): Optional, for the Timeline view (hidden)
- Project Day 0 (Date): Helper for the formula: the customer's Start date, filled by the Task Generator (hidden)
- Program length (Number): Helper for the formula: 60, 75 or 90, filled by the Task Generator (hidden)

Statuses, in this order: Not started, In progress, Waiting on client, In review, Done, Won't do. Every task starts as "Not started".
Main table: show Task ID, Task, Module, Status, Owner role, Assignee, Due date, Client-facing, Repeats, Depends on, Definition of done, Notes. Hide Section, Start day, Due day, Start date, Project Day 0, Program length.
Due date formula: Due date = Project Day 0 + Due day. For programs shorter than 90 days, tasks with a Due day above 10 are compressed: Due day × Program length ÷ 90, rounded. Tasks in section P9 are counted from the end instead: Due day − 90 + Program length. Tasks in section P0 get no date. If Project Day 0 is empty, Due date stays empty. Leave Project Day 0 and Program length empty in the library.
Views:
- Board: Columns = Status. Cards show Task ID, Task, Assignee, Due date.
- By section: List grouped by Section (P0 → P9), sorted by Task ID.
- By module: Grouped by Module, then Section.

Create these sections and tasks, in this order. Fill Task ID, Module, Owner role, Client-facing, Start day, Due day, Repeats, Depends on and Definition of done ("Done when") from each line. Add the "Subtasks" as a checklist under the task.
