Request 1

Stale should mean unused, not unedited

"P4 uses the last edit time as the reason to be considered stale. Can we consider stale the ones that have had no enrolments in a year?"

An earlier version of this note said enrolment data was unavailable. That was wrong. The first round tested nine per-workflow routes and concluded the data did not exist. It never tested the list endpoint, and it passed the wrong identifiers: the modern API calls this workflow 7870191 while the legacy API calls it 7023659, so every per-workflow probe was asking about a workflow that does not exist under that name.

What is actually available

GET /automation/v3/workflows returns, for each workflow, contactCounts — how many records it has enrolled in its lifetime, and how many are inside it right now. That is real enrolment data and it is now part of the audit.

  • Lifetime enrolled — the total ever put through it. Zero means it has never acted on a single record, whatever its edit date says.
  • Currently enrolled — records sitting inside it today, mid-sequence.

What is still missing

A date. Nothing returns "last enrolled on". Per-workflow performance and enrolment routes do not exist under either identifier — that part of the original finding holds. Property history records automation writes as enrollmentId:…;actionExecutionIndex:N, naming the enrolment rather than the workflow, and no endpoint resolves one to the other.

How to get the year window anyway

The count is a running total, so the difference between two runs is enrolment during that period. From the second monthly run onward the audit can report "enrolled 0 records since last month" per workflow, which is the question originally asked, answered continuously rather than looked up once. Nothing to build beyond storing the previous run.

What it changes today

P4 no longer rests on edit dates alone. A workflow that is switched on and has never enrolled anyone is now flagged on measured evidence rather than inferred from when someone last touched it, and those rows sort to the top of the tab.

Coverage is partial The legacy endpoint returns 581 of the 646 workflows, and matching them to the modern list by identifier and name reaches most but not all. Anything unmatched reads "not measured" rather than zero — an unmeasured workflow and an unused one must never look the same in a column someone acts on.
Request 2

Fill rate on the unused fields

"Can we get for P6 a fill rate on those properties?"

Built, and it splits the list into four very different groups

Every one of the 2,249 fields now carries an exact count of how many records hold a value, against the object's total. Combined with request 3, the 332 the audit flagged as unreferenced turn out not to be one population at all.

Of the 332 flaggedFieldsWhat to do
Empty — no record holds a value154Archive. Nothing references them and nothing has ever filled them.
Nearly empty, no write seen50Archive after a glance. A residue of values, no recent activity.
Written in the last 12 months54Leave alone. Something is actively filling these today.
Written, but longer ago73Judgement. The date and the source say whether it retired or went quiet.

The first row is the win: 154 fields can be archived with no further checking. The third is the save — those 54 would have been archived under the original guidance, and something would have broken.

Fields with no records behind them The quote object holds 195 properties and zero records. Fill rate is undefined there rather than zero, and the workbook leaves those cells blank rather than reporting 0% — an empty object is a different finding from an unused field.
Request 3

When a field was last written, and by what

"Can Claude export the property history to see when it was the last time those properties were updated on a record?"

Built as a sample, and the "by what" matters more than the "when"

HubSpot returns history one record at a time, so asking every record is not a report but a migration. Instead, the 200 most recently modified records per object are read — the right bias, because a field still in use shows up there first. 1,037 of the 2,249 fields had a write in that window.

Each field now reports its most recent write and what caused it, in plain terms: Automation, Integration sync, Form submission, Import, Someone typing. That last one is what the audit could never see before — a field maintained by hand looks identical to a dead one until you know who writes it.

What it found here

Of the 332 flagged fields, 54 were written within the last 12 months — 35 by an integration, eight by record merges, four calculated by HubSpot, four by form submissions and three by automation. Those are live fields that happen to sit outside any workflow, list or active form.

The riskiest single case: "Which distribution channels are you interested in?" is filled on well under 1% of contacts and was last written by a form submission the day before this was measured. On fill rate alone it looks abandoned. It is a working form field, and a low fill rate is exactly what a form field should look like — only the fraction of people who submitted that form will ever carry a value.

That case forced a change to how the verdict is calculated. Recency and source now outrank fill rate: a field written last month is in use at 0.1% fill, while a field at 40% fill last written in 2021 is a fossil. Ordering it the other way round marked live form fields as empty, which is the precise mistake this measurement exists to prevent.

A sampled date is a floor, not a ceiling A field may have been written more recently on a record outside the 200 sampled. Treat a recent date as proof of life; treat the absence of one as "no evidence found", never as proof the field is dead. The fill rate is exact — only the dates are sampled.

Where this leaves P6

The phase that previously said "check three things yourself for each of 332 fields" now sorts itself, and the tab opens on the fields that need a decision rather than the ones that do not.

What is in the workbook now

The P6 tab leads with a plain-language verdict per field, then fill rate, record count, last written, what wrote it, and everything seen writing it — sorted so the most recently written are at the top, because those are the ones a decision could get wrong. The full Properties tab carries the same three measurements for all 2,249 fields.

These numbers age Fill rate and last-written are a snapshot of 4 September 2026. Re-run before acting if more than a few weeks have passed — a field that looked safe in September may be in use by November, and the archive decision would then be the wrong one.
